以 `index.js` 为唯一入口，统一装配三个并行运行时：
- HTTP REST：通过 `express()` 构建 app，按业务分期挂载路由（auth/workorder/kb/tree-assets/reports/drone/uploads/device-registry），并注册 `/ws` WebSocket 通道；
- MQTT 接入层：内嵌 `aedes` Broker（端口由 `MQTT_PORT` 配置，默认 1883），同时作为客户端订阅 `smart-garden/#`，将 sensor status 解析后写入 `state.js` 内存 Map 并通过 `db.js` 落库 `sensor_data`；
- 定时任务：每 5s 运行离线检测（`makeOfflineWatcher`）、每 60s 清理 7 天前的传感器数据。

内部依赖方向自顶向下分层：
- 路由层（`routes.js`）暴露通用 REST（设备、历史、告警、摄像头 PTZ、AI 识别、灌溉控制），通过 `setPublishControl` / `setClientCounter` / `setAi` / `setIrrigation` 回调注入运行时能力；
- 领域引擎（`rules.js` 阈值告警、`irrigation.js` 闭环策略、`ai.js` 推理管线、`uploads.js`+`multipart.js` 图片上传、`tree-assets.js` 苗木档案）独立于 HTTP 层，仅依赖 `db.js` 和 `state.js`；
- 持久化层（`db.js`）基于 Node 内置 `node:sqlite` 的 `DatabaseSync`，使用 WAL 模式与预编译语句；设备目录初始数据来自 `devices.json`（ESM `with { type: 'json' }` 导入）。`state.js` 维护内存中的 `devices` Map 并提供快照导出。

跨模块协作通过回调注入（而非全局单例）完成：`index.js` 在启动后将 `broadcast`、`irrigation`、`aiEngine` 注入到路由与规则中，保证各子模块可被单独测试替换。
