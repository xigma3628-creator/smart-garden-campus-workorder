The module has three layers:
- `server/src/drone.js` (data layer): responsible only for SQLite table creation (`drone_missions`/`drone_frames`), row→object mapping (`toMission`/`toFrame`), route normalization (`normalizeRoute`), mission-number generation (`nextMissionNo`), and image persistence path computation (`DRONE_FRAME_DIR`); it holds no business state machine.
- `server/src/routers/drone.js` (interface layer): exposes `/api/drone/*` REST endpoints on an Express Router, calls the data methods in drone.js, and carries the mission state machine (`planned→flying→done/aborted`), multipart frame upload, inference requests to the external `/infer` service, alarms triggered by high-confidence pest detections, and scheduled compensation retries (`startDroneInferenceRetry`).
- `server/simulator/simulate.js` (standalone executable script): connects via the mqtt client to `mqtt://127.0.0.1:1883` and publishes simulated telemetry for 16 devices to `smart-garden/{type}/{id}/status` on a 2-second cycle; supports drought fault injection via the SIM_FAULT environment variable, and subscribes to the irrigation valve downstream control topic for two-way linkage.
Dependency direction: router → drone.js → db.js/sqlite; the simulator is a standalone entry, not coupled to the web routes.
