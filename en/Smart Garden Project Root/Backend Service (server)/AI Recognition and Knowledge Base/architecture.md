The module consists of two parallel service pipelines, both operating SQLite directly through `server/src/db.js`:
- AI recognition pipeline (`ai.js`): creates the `ai_results` table at startup; `recognize(cameraId, source)` returned by `createAiEngine` first calls `inferFromModel`, sending a frame-grab request to `INFERENCE_URL` (default `http://127.0.0.1:3101/infer`), and automatically falls back to `mockInference` on failure; the class mapping merges `classes_map.json` with the built-in `TAXONOMY` on two tracks; results are uniformly persisted via `insertAiResult` and trigger alarms/broadcasts.
- Knowledge-base pipeline (`kb.js`): maintains the `kb_entries` table and the optional FTS5 `kb_fts` (trigram tokenizer), supporting CRUD by category (tree/pest/maintenance_standard); `importEntries` imports in pest→tree→maintenance_standard order to resolve the id references in `common_pests`; search tries FTS MATCH first and degrades to LIKE for short terms or when FTS is unavailable.
- REST router layer (`routers/kb.js`): exposes `/api/kb/*` endpoints on an Express Router; query endpoints are unauthenticated, write endpoints use `requireAuth('admin')`; the QA endpoint first retrieves Top-K references and then calls `rewriteWithLlm` to generate the answer.
Dependency direction: router → kb → db; ai → frame-grabber / cameras / state / rules; the two pipelines are not coupled to each other.
