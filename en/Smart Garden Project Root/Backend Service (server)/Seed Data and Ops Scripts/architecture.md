All scripts are top-level ESM entry points (.mjs) that depend directly on the runtime modules in server/src, falling into two categories by responsibility:
- Data seeding: import-kb.mjs writes garden_kb.json into kb_entries via importEntries/ftsOk from ../src/kb.js; seed-trees.mjs uses the device latitudes/longitudes in devices.json as anchors and mulberry32 fixed-seed random numbers to idempotently generate about 60 saplings in the tree_assets table with INSERT OR IGNORE.
- API simulation and evaluation: simulate-drone.mjs calls /api/auth/login → /api/drone/missions → ffmpeg frame extraction → uploads and finishes via /api/drone/frames; kb-eval/eval.mjs samples 20 questions from the db and calls /api/kb/qa to produce questions.json and eval-report.json, while kb-eval/selfcheck.mjs runs an end-to-end self-check against /api/kb/*.
The dependency direction is one-way: scripts → src/db.js, src/kb.js, src/tree-assets.js; business code never references them in reverse. Configuration is uniformly injected via process.env (KB_SEED_FILE, API_BASE, DRONE_BASE/USER/PASS) or command-line arguments, avoiding hard-coded runtime environments.
