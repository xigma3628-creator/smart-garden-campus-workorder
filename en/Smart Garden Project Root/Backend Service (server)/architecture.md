server is the Node.js application root: `src/index.js` starts the Express service and mounts the business routers. The core runtime (core_runtime) maintains, in-process, the MQTT broker, WebSocket broadcast, in-memory device state catalog, and SQLite time-series storage, and is consumed jointly by drone_simulator, ai_kb, scripts, and tests.
- Communication contract: HTTP REST is aggregated and exposed by `src/routes.js`; device telemetry and real-time events travel over Aedes MQTT topics (e.g. `device/...`, `drone/...`), live frames are pushed via WebSocket; file uploads are persisted by `src/multipart.js` / `src/uploads.js` and then backfilled with results by the AI inference callback.
- Data boundary: SQLite schema is initialized by `src/db.js`; all writes go through the dual-write of in-memory snapshot + persistence in `state.js`; AI and the knowledge base are decoupled — camera frames are stored first, then `ai.js` inference is triggered.
- Runtime extension points: `simulator/simulate.js` and `scripts/seed-trees.mjs`, `simulate-drone.mjs` reuse the same MQTT publish interface to inject simulated data; the `test/*` acceptance scripts drive end-to-end scenarios through the three channels HTTP/MQTT/WS.
