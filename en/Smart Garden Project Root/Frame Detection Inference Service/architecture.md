The module consists of three layers:
- Interface layer `app.py`: the FastAPI application, which loads the model asynchronously in a background thread via `lifespan`; it exposes two endpoints, `GET /health` (health check, including `loaded/status/error`) and `POST /infer` (multipart image input).
- Adapter layer `model_adapter.py`: defines the abstract base class `BaseDetector` (unified weight download, the `idle/loading/ready/error` state machine, and `load/warmup/infer` hooks), and implements two backends, `YoloDetector` (ultralytics) and `OnnxDetector` (onnxruntime CPUExecutionProvider with built-in letterbox + NMS); `build_detector()` selects the concrete implementation based on the `MODEL_BACKEND` environment variable.
- Data mapping layer `classes_map.json`: maps the model's generic classes to the project taxonomy (pest/growth); the backend reads it to complete business classification.
The dependency direction is one-way: `app.py → model_adapter.BaseDetector`, with no reverse dependency on the backend. Weight files live in `weights/`; on first startup they are downloaded automatically from ultralytics assets or a gh-proxy mirror as `.pt` or `.onnx`. If the download fails, the service still starts, but `/health` reports error and `/infer` returns 503 so the backend can degrade.
